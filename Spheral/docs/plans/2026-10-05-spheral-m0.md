# Spheral M0: Spheral runs here — Implementation Plan

> **For agentic workers:** execute task by task with one sub-agent per task; the controller reviews each task's
> diff and numbers before the next starts. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spheral at the pinned development commit runs on the Mac Studio; its cost per particle per step in 3D and
axisymmetric form, its memory per particle and its scaling with processes are measured; Python subclasses of the
equation-of-state, strength and damage classes are shown to reproduce the built-ins, with their added cost measured;
and the decision gate of spec §5 is evaluated on those numbers.

**Done when** (spec §14): the costs and the subclass test are recorded as measured facts in the spec.

**Spec:** `docs/superpowers/specs/2026-10-02-spheral-large-fragments-design.md` — §2 (facts), §4.4 (environments, tests,
names), §5 (M0), §12 checks 1–2, §14, §15 (risks M0 retires). M1 is planned separately; the cluster half of M0 is
deferred (Asha, 2026-10-05: develop for the Mac Studio now, the cluster later).

## Facts established while writing this plan (2026-10-05)

These replace assumptions in spec §2 and §5 and are written into the spec by Task 8.

1. **LLNL's prebuilt image cannot run on Apple Silicon.** `ghcr.io/llnl/spheral:latest`
   (`sha256:fee841c59f214fb0baed1a3ed3d0fe8a3c0c09c083f2ef1d62b035d5392a5366`, built 2026-09-28 22:07 UTC) pulls and
   starts under Rosetta, but `import Spheral` dies with `Illegal instruction`. Spack built its libraries for target
   `x86_64_v4` (97 of 200 package specs; the rest generic `x86_64`), and `libSpheral_CXX.so` contains 8,751 instructions
   on AVX-512 `zmm` registers. Rosetta inside Docker reports `sse4_2 avx avx2 fma bmi2` but no AVX-512. The Spheral
   CMake flags carry no `-march`; the target comes from Spack's compiler wrapper on the GitHub runner, so any future
   `:latest` may or may not run. Python, numpy 1.26.4 and mpi4py in the same image do run.
2. **The pinned commit carries the stress-rotation fix.** The image's source is develop at `116c71f`
   (2026-09-28 16:51 UTC), which is the merge of PR #520 "Bugfixes for Strain-Porosity model and Jaumann rate
   definition, fixes #534", and is develop's head on 2026-10-05. `src/SPH/SolidSPH.cc` there evaluates
   `spinCorrection = (spin*Si - Si*spin).Symmetric()` with `spin = localDvDxi.SkewSymmetric()`. Damage in axisymmetric
   runs (PR #518, 2026-08-14) is an ancestor.
3. **Route chosen: a native arm64 source build** (Asha, 2026-10-05), in an `ubuntu:24.04` arm64 container under the
   Docker Desktop already installed, following LLNL's own `Dockerfile` at `116c71f` (Spack TPLs through
   `scripts/devtools/tpl-manager.py --spec spheral%gcc`, then `host-config-build.py`, `make python_build_env`,
   `make python_runtime_env`, `make Spheral_CXX`, `make`, `make install`). Untested upstream on arm64; the spec
   estimates 3–4 hours.
4. **The machine.** Mac Studio, Apple M5 Max, 18 cores (6 + 12), 64 GB. Docker Desktop 29.8.2 with Rosetta on, set by
   Asha on 2026-10-05 to 18 CPUs and about 47 GB of memory for its Linux VM; 1.5 TB free on the host disk. The repository
   path (`/Users/ashajain/MIT/particle_formation`) no longer contains spaces. The host's Open MPI 4.1.8 is not used:
   Spheral runs against the container's own MPI, inside Docker's VM, so the VM's CPU limit caps the process count.
5. **The regression examples.** `TensileRod-1d.py` compares its output with stored reference files at a tolerance of
   1e-4 (`--checkRef True`), checks domain independence on 4 processes and restarts. `TaylorImpact.py` has no stored
   reference: its ATS lines at level 100 only *generate* snapshots, so for it "reproduces" means "runs to completion in
   2d, RZ and 3d on 1 and 8 processes".

## Global constraints

- **Interpreters.** `PY=/Users/ashajain/miniforge3/envs/drama_env/bin/python` runs the host-side tests and the
  analysis. Everything that imports Spheral runs inside the container through the launcher of Task 2. Nothing in
  `drama_env` imports Spheral, Spheral's Python never imports `reentry_model`.
- **Paths.** Repository at `/Users/ashajain/MIT/particle_formation`, mounted read-write at `/work` in the container.
  Spheral installed at `/opt/spheral` in the image (Task 1 fixes the exact prefix and records it).
- **Outputs** go to the git-ignored `spheral_output/`; only the pin file, the Dockerfile, the launcher, the scripts,
  the tests, the collected benchmark table and the spec amendment are committed (CLAUDE.md: outputs ignored, inputs
  and measured facts committed).
- **Run names encode the whole configuration** (CLAUDE.md), e.g.
  `bench_3d_dx2.20mm_n18_dmgoff_steps100_116c71f`, and a study resumes by skipping any run whose `summary.json`
  exists.
- **Exit codes** as in `reentry_model`: 0 ok, 1 a model failure, 2 bad arguments or a missing optional piece (no
  Docker, no image).
- **Commits on `main`** (Asha, 2026-10-05), one per task, message a scope prefix and a sentence describing the
  behaviour, e.g. `spheral_frag: native arm64 Spheral image at 116c71f ...`, ending with the attribution line.
- **Machine idle during timed runs** (Tasks 5–7): nothing else heavy runs; each timed run records the load average
  before it starts and refuses to start above 2.0 unless `--force`.
- **No silent tolerance changes.** If an upstream regression comparison fails on arm64, the task reports the size of
  the difference and stops; it never loosens a tolerance.

## Review focus

1. **The build is reproducible from the repository alone**: the committed Dockerfile clones `116c71f` by full SHA, and
   the image records the Spack spec of every TPL (`spack find -lv` committed next to the pin). → Task 1.
2. **MPI works inside Docker**: Open MPI refuses to run as root and its shared-memory transport fails in Docker's default
   64 MB `/dev/shm`. The launcher must set both, and a 2-rank test must prove it. → Task 2.
3. **The `spheral` marker skips cleanly** when Docker is stopped or the image is absent, without hanging the normal test
   loop. → Task 2.
4. **Timing excludes start-up and is honest about Rosetta**: no Rosetta is involved in the native build, so the
   numbers are native arm64; the report says so, since the cluster will be x86-64. → Task 5.
5. **The subclass comparison is made on the same particles and the same steps**, and differences are reported in ULPs
   or relative terms, not as pass/fail alone. → Task 7.

- [ ] **Step 5: `pin.json`** holds: commit SHA and date, upstream PR, image tag, local image ID, build date, build wall

### Task 2: Launcher, the `spheral` marker and output directory

**Files:**
- Create: `spheral_frag/container/spheral` (executable bash)
- Modify: `pytest.ini`, `tests/conftest.py`, `.gitignore`
- Create: `tests/test_spheral_frag_runner_container.py`

- [ ] **Step 1: Launcher.** `spheral_frag/container/spheral [-n NPROC] script.py [args...]` runs

  ```bash
  docker run --rm --platform linux/arm64 \
      --shm-size=8g \
      -e OMPI_ALLOW_RUN_AS_ROOT=1 -e OMPI_ALLOW_RUN_AS_ROOT_CONFIRM=1 -e OMP_NUM_THREADS=1 \
      -v "$REPO":/work -w /work/"$RELDIR" \
      "$IMAGE" \
      mpirun -np "$NPROC" --bind-to none /opt/spheral/bin/spheral "$@"
  ```

  with `IMAGE` read from `pin.json`, `RELDIR` the caller's directory relative to the repository (so relative paths keep
  working), `-n 1` by default (no `mpirun` wrapper when 1, so start-up is not inflated). Exit 2 with a one-line message
  when Docker is not running or the image is missing. `SPHERAL` (spec §4.4) is documented as this launcher's path.
- [ ] **Step 2: Marker.** Add to `pytest.ini`:
  `spheral: needs the Spheral container image (spheral_frag/container/pin.json); skipped automatically when the
  launcher cannot import Spheral`. In `tests/conftest.py`, extend `pytest_collection_modifyitems`: probe once per
  session with `spheral -c "import Spheral"` under a 120 s timeout, cache the result, skip `spheral` items on failure
  with the probe's message. The existing `drama` logic stays unchanged. (Deviation from spec §4.4's wording "when
  Spheral is not importable": Spheral is never importable in `drama_env`, so the probe goes through the launcher.)
- [ ] **Step 3: `.gitignore`** gains `spheral_output/`.
- [ ] **Step 4: Tests** (`@pytest.mark.spheral`): Spheral imports and reports the pinned SHA if Spheral exposes one,
  else `pin.json`'s commit is checked in Task 1 only; `-n 2` runs an mpi4py script whose ranks report size 2 and
  ranks {0, 1}; a script in a subdirectory resolves a relative input file; the launcher returns 2 when given a missing
  image tag. Plus one unmarked test that the conftest probe skips (not errors) when the launcher is replaced by
  `false`.
- [ ] **Step 5:** Run `"$PY" -m pytest tests/test_spheral_frag_runner_container.py -q` and the normal loop
  `-m "not drama and not reference"` to confirm nothing else changed. Commit.

### Task 4: Stress rotation, checked numerically

Spec §5 asks only for the source check (Task 1 Step 4). This task turns it into a measurement, because the rotation
term is the one known bug that would corrupt the slow replay. Small and cheap; Asha may drop it at review.

**Files:**
- Create: `spheral_frag/m0/rigid_rotation.py`
- Create: `tests/test_spheral_frag_runner_rotation.py`

- [ ] **Step 1:** A 2D square of AA7075-like solid (ρ 2,813 kg/m³, E 71.7 GPa, ν 0.33, ConstantStrength with a yield
  far above the stress) at about 20×20 particles, with a uniform initial deviatoric stress S₀ (e.g. a pure shear of
  10 MPa), given the rigid-rotation velocity field v = ω × x, ω such that a quarter turn takes 50–100 steps. Advance a
  quarter turn.
- [ ] **Step 2: Check:** in the interior particles, the stress equals R S₀ Rᵀ for the rotation actually turned through
  (measured from particle positions) within 1 % of |S₀|, and the von Mises stress stays within 1 % of its start. A
  wrong-sign rotation term rotates the stress by −2θ relative to the body and fails by order one.
- [ ] **Step 3:** Test (`spheral`) running it at reduced size; commit with the measured error.

### Task 5: Benchmark script

**Files:**
- Create: `spheral_frag/m0/bench.py` (runs under Spheral)
- Create: `tests/test_spheral_frag_runner_bench.py`

- [ ] **Step 1: The body.** A 100 mm AA7075 sphere at rest: 3D on a lattice clipped to radius 50 mm; axisymmetric
  (`RZ`) on the half-disk of the meridional plane. Particle count within 5 % of V/Δx³ (3D) or (πR²/2)/Δx² (RZ).
  Material for timing only (Asha, 2026-10-05: time with `SteinbergGuinan`, whose cost is what production pays):
  `SteinbergGuinanStrength` with the Grüneisen equation of state, both with the aluminium parameters of Spheral's
  material library but the density set to AA7075's 2,813 kg/m³. The library's atomic weight (24.032, spec §2 traps)
  and the Grüneisen temperature relation do not matter for timing; the script says so in a comment and in
  `summary.json` (`"material": "timing only"`). Damage off or `ProbabilisticDamageModel` with its documented defaults
  and a fixed seed. To keep strength and damage doing real work, a small uniform expansion velocity v = ε̇ x with
  ε̇ = 10 s⁻¹ is imposed at the start. `SolidSPH`, `CheapSynchronousRK2`, Courant 0.25, no output during timed steps.
- [ ] **Step 2: Timing.** Arguments: `--geometry {3d,rz} --dx-mm --damage {on,off} --steps 100 --warmup 10 --out DIR`.
  Measure separately: import and start-up, body generation, `warmup` steps (discarded), then each timed step
  individually. Write `summary.json`: geometry, Δx, particle count, process count, damage, start-up time, per-step
  wall time (mean, median, min, max), processor time per particle per step (= processes × median step / particles),
  Spheral's time step dt, peak resident memory per process and in total (via `resource.getrusage` reduced over MPI),
  memory per particle, the load average at start, and the content of `pin.json`. Run name per the global
  constraints; skip the run if its `summary.json` exists.
- [ ] **Step 3: Tests** (`spheral`): 3D at Δx 10 mm and RZ at Δx 5 mm, 5 steps: the summary exists, the particle count
  is within 5 % of the formula, all times are positive, the second invocation is skipped. Commit.

  trampoline does not allow that, **stop and report** what it does allow — that decides the C++ branch.
- [ ] **Step 4: Compare** on Task 5's body (RZ at 1.1 mm and 3D at 3.0 mm, 18 processes, 100 steps, fixed seed):
